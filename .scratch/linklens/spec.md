# Spec: linklens —— LinkLens 终端网络诊断工具

Status: resolved

## Problem Statement

用户在选节点、验代理时需要频繁回答一类问题：「我现在这个出口 IP 干不干净？Claude/GPT 认不认它？DNS 和 WebRTC 会不会漏？各个网站的分流出口是不是我想要的那个？」目前只能开着网页版 ip.net.coffee 逐页点检测，浏览器环境还引入了指纹、WebRTC、系统 DNS 之外的不确定性。用户想要一个在终端里常驻、随开随测、结果可信且能跨天对比的工具。

## Solution

一个纯交互式的终端 TUI（Rust 单二进制），提供七项网络诊断能力，使用 net.coffee 后端接口：IP 查询、Claude 出口检测、GPT 出口检测、IP 评分、DNS 泄漏检测、WebRTC 泄漏检测、网络连通测试。界面采用卡片式终端仪表盘：三列卡片网格、卡片+徽章+key-value 行、emoji 国旗、Nerd Font 图标、语义五色。检测判定逻辑（场景评分公式、受限地区表、泄漏判定）逐字按接口报告定义实现（权威依据：仓库net.coffee 接口报告），因此结论与上游接口报告一致，且原生 HTTP/DNS/STUN 探测比浏览器更接近真实链路。

## User Stories

1. 作为选节点的用户，我想要启动一个终端命令就进入功能导航界面，以便随时在七个检测功能间切换。
2. 作为用户，我想要首页自动显示我的国内出口 IP（主出口与备用出口分卡显示），以便识别多出口网络环境。
3. 作为用户，我想要看到出口 IP 的中文归属地与运营商、家宽/机房/商业专线属性徽章，以便一眼判断节点类型。
4. 作为用户，我想要首页对 6 个代表性目标（国内外各半）做多次计时取中位数的连通小卡，以便快速判断线路质量。
5. 作为用户，我想要 37 站分流出口探测并把相同出口去重汇总（带国旗与来源站点），以便核验代理分流规则是否生效。
6. 作为用户，我想要在 IP 评分页输入任意 IPv4/IPv6 进行深度查询，以便评估候选节点 IP 而不仅限当前出口。
7. 作为用户，我想要 Claude 检测页并行展示国内出口、Cloudflare 出口、Claude 出口三张 IP 卡，以便分清「我以为的出口」和「Claude 看到的出口」。
8. 作为用户，我想要 Claude 出口的信任分卡片（0-100 分值、纯净度档位徽章、渐变刻度条），以便量化节点纯净度。
9. 作为用户，我想要 Claude 出口属性卡片（地区/城市/IP 属性/ASN/运营商），以便了解出口背景。
10. 作为用户，我想要 Claude 出口安全检测卡片（VPN/代理/Tor/机器人/滥用记录逐项徽章），以便排除风险信号。
11. 作为用户，当出口命中受限地区时，我想要信任分强制按 0 处理并显示红色「不可访问」警示（不再显示时延），以便第一时间知道这个节点不该尝试。
12. 作为用户，我想要 Claude 服务状态行（官方服务是否正常），以便区分「我的节点问题」和「Claude 本身故障」。
13. 作为用户，我想要 Claude 可用性探测给出时延分档（正常/良好/较慢/不可访问），以便评估链路质量。
14. 作为用户，我想要 GPT 检测页提供与 Claude 页完全同构的检测（出口源换成 chatgpt.com，探测目标含 api.openai.com），以便同样地评估 OpenAI 链路。
15. 作为用户，我想要 DNS 泄漏页一键发起随机子域名探测（走系统 resolver），以便验证本机真实 DNS 行为。
16. 作为用户，我想要 DNS 泄漏页回读并列出所有解析器出口 IP（带国旗），以便看清 DNS 链路走了哪些地区。
17. 作为用户，我想要 DNS 泄漏三态判定（泄漏/已加密未暴露/干净），以便直接得到结论而不必自己解读。
18. 作为用户，我想要 WebRTC 页通过 STUN 获取公网 UDP 地址（IPv4 与 IPv6 都要采集），以便发现代理下的 UDP 真实出口。
19. 作为用户，我想要 WebRTC 泄漏判定（公网 UDP 地址与 HTTP 出口不一致即泄漏），以便知道是否需要关 WebRTC 或换 TUN 模式。
20. 作为用户，我想要 IP 评分页展示深度聚合信息（ai_verdict 判词、多源定位对比、位置/ASN/公司历史轨迹、机房邻居、反查域名含 pending 轮询），以便全面体检一个 IP。
21. 作为用户，我想要 IP 评分页的 v2 增强区块（C 段热度趋势、BGP 拓扑、12 家 DNSBL、Radar 人机比、同 ASN 公司），以便获得风险侧写。
22. 作为用户，我想要按 TikTok/社媒/AI 三场景各自的 0-10 场景评分（含地区硬门槛：block 归零、partial 封顶），以便直接回答「这个节点能不能干某件事」。
23. 作为用户，我想要 Claude/GPT 检测历史被持久化保存（同 IP 24 小时内去重、重启仍在），以便跨天对比节点纯净度变化。
24. 作为用户，我想要最近查询过的 IP 可快速重新检测，以便省去重复输入。
25. 作为用户，我想要一个隐藏 IP 开关把界面上的 IP 打码，以便放心截图分享到群里。
26. 作为用户，我想要终端窄于 90 列时三列卡片自动降级为单列，以便小窗口仍可用。
27. 作为用户，我想要所有探测在失败/超时时给出明确的状态呈现（超时/不可达，而非报错堆栈或卡死），以便任何网络环境下工具都不添乱。
28. 作为用户，我想要全中文文案、Nerd Font 图标与语义五色（绿=结论/黄=警示·冷却·配额/红=错误·泄漏/青=强调/暗灰=次要）贯穿所有页面，以便信息密度高且观感统一。

## Implementation Decisions

- **技术栈**（ADR-0001）：ratatui + tokio + reqwest（rustls-tls）+ serde_json；DNS 泄漏用 hickory-resolver 发 UDP 53 查询且必须按系统 resolver 配置发询；WebRTC 用手写 RFC 5389 STUN Binding（只读 XOR-MAPPED-ADDRESS），否决 webrtc-rs 与阻塞式 ureq。
- **架构**：横切分层 `net/`（net.coffee API 客户端 + 第三方探测源：cdn-cgi/trace、ip138、my.ip.cn、CDN 响应头）→ `detect/`（检测器纯逻辑）→ `ui/`，另加 theme/icon；依赖单向 ui→detect→net。
- **测试接缝**（已与用户确认）：唯一接缝是「纯函数 vs IO 壳」——net 解析、detect 判定、STUN 编解码、限流映射、历史去重全部是纯函数；HTTP/DNS/STUN 真实收发与 ratatui 渲染不进单元测试。
- **判定规则依据接口报告**（依据仓库net.coffee 接口报告 §2、§3）：受限地区表（CN/HK/MO/RU/KP/IR/SY/CU/BY/VE，命中强制 0 分）；场景评分公式与地区硬门槛（block→0、partial→封顶 5）；信任分档位（≥95/≥80/≥50/≥25）；时延分档（<250ms 正常/<500ms 良好）；DNS 泄漏判定（解析器含 CN 且出口非 CN）；WebRTC 泄漏判定（公网 UDP ≠ HTTP 出口）；连通测试 1 次预热 + 多轮取中位数；隐私过滤私网段清单采用。
- **行为与上游接口报告的两处有意差异**：不发送 `/api/session` 统计上报；无浏览器指纹/设备信息模块（终端环境不存在此维度）。其余语义采用：Claude/GPT 页只测本机出口，评分页支持任意 IP。
- **质量红线**（源自旧实现审查，重建不得重蹈）：WebRTC 候选采集必须含 IPv6；公网探测超时用 8s（非 5s）；DNS token 用真随机 24 位；用户文案遵守 GLOSSARY 的 Avoid 词（如「评分查询」），「泄漏/泄露」统一「泄漏」。
- **数据持久化**（ADR-0002）：历史记录存仓库内 `.data/` 目录（目录内放内容为 `*` 的 .gitignore 自忽略）；Claude/GPT 检测历史同 IP 24h 去重。
- **命名约束**：项目名是占位、后续会改名；除二进制名随 Cargo.toml 同步调整外，任何命名不得焊死当前项目名。
- **界面**：卡片是基本布局单位；三列网格、<90 列降级单列；徽章用语义底色；国旗用 emoji；品牌图标用 NF md-* 字形近似；不引裸边框块和裸颜色常量，一律走主题助手。
- **待修陷阱**（研究报告 §5、§6 实测结论）：iprisk 响应的 `ip` 可能是 /24 段代表 IP 而非请求 IP，界面需如实标注；`/api/geoip` 非法输入返回 502、`/api/ip/lookup` 返回 400，错误处理需区分；DNSBL/heat 不支持 IPv6 时隐藏对应区块；淘宝/微信等目标的连通计时以「连接+TLS 握手完成」为准，不等 body 下载。

## Testing Decisions

- **只测接缝上的外部行为**：给定输入（API 响应样例文本/JSON、trace 文本、STUN 字节、探测事实结构），断言输出（解析结构、判定结论、评分、档位），不测内部实现细节。
- **被测模块**：net 层解析函数（trace、ip138、my.ip.cn、CDN 头）、detect 层全部判定（场景评分公式逐项扣分、受限地区表、原生/广播推导、DNS/WebRTC 泄漏判定、信任分档位、portscan 429 限流映射、历史 24h 去重）、STUN 编解码（含 XOR-MAPPED-ADDRESS 正反例）。
- **测试数据**：直接采用net.coffee 接口报告里的真实响应样例作为 fixture（含段代表 IP、pending 轮询、空 dns_servers、bogon 等边界样例）。
- **方法**：每张票按 tdd 推进（先红后绿）；仓库当前无既有测试（全新重建），测试与被测代码同 crate 放置，遵循 Rust 惯例。
- **不测**：真实 HTTP/DNS/STUN 收发（以研究报告的 curl 验证结果为准做集成冒烟）、ratatui 渲染（以用户 NF 终端人工验收）。

## Out of Scope

- 全球拨测页（20 节点 ping 三件套）、Cloudflare 测速页、端口扫描与 pingcheck 卡片（属 v2）
- WHOIS 页、服务状态总览页、新闻页
- Claude/GPT 页的「模拟检测任意 IP」模式（v2）
- CLI 子命令模式、Turnstile/reCAPTCHA 人机验证（TUI 无法实现）
- `/api/session` 统计上报、Google Analytics 等统计能力
- 项目改名本身（本规格只约束「不焊死名字」）
