# 用户级历史目录与双命令入口

Status: implemented
Supersedes: [0002-local-data-dir.md](0002-local-data-dir.md)

## 问题

LinkLens 可从任意目录运行，并可存在多个工作树。仓库级数据目录会把同一用户的历史分散到不同位置。产品名称已确定，历史路径应具有稳定的用户级归属。

## 决策

历史目录固定为用户主目录下的 `.config/linklens/datas/`。主命令 `linklens` 与短命令 `llens` 共用应用逻辑和历史文件；文件名、JSON 格式、每平台最近 6 条及同 IP 24 小时去重语义保持一致。该路径按用户明确要求使用，不随工作目录或 `XDG_CONFIG_HOME` 改变。

主目录解析失败时返回 IO 错误，不回退到当前目录。检测仍可展示本次内存历史，磁盘持久化不可用。

## 备选方案

- 仓库根 `.data/`：适合早期工作树内调试，但多个 checkout 的历史隔离不符合用户级使用方式。
- 完整 XDG 目录选择：用户明确指定 `~/.config/linklens/datas/`，本决策采用固定位置。
- 仅提供 shell 别名：依赖用户 shell 配置；采用第二个薄二进制入口，使 Cargo 安装同时提供两个命令。

## 后果与迁移

所有工作树共用每个平台的历史文件。迁移现有文件时按记录时间合并，同 IP 保留最新记录，每平台保留最近 6 条；源文件和仓库外备份保留。运行时只读写新目录，不自动扫描其他仓库。

`src/history.rs` 负责路径与持久化，默认测试验证目录推导和历史纯逻辑。磁盘迁移、任意目录启动以及两个命令的共享历史需单独验证。多个进程同时写同一历史文件仍采用现有覆盖写语义；本次迁移不引入跨进程锁。
