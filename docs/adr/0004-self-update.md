# LinkLens 自更新边界与用户触发

Status: implemented

CLI、TUI、官方构建标识和双命令安装流程已实现；平台运行验收状态见下方验收记录。

## 问题

LinkLens 提供两个共用应用逻辑的命令，并支持官方 Release 安装与源码安装。自更新需要兼顾升级便利性、安装来源边界和终端诊断的连续操作。

## 决策

提供等价的 `linklens update` 与 `llens update` 命令，同时在 TUI 中自动检查版本。下载与程序替换必须由用户执行更新命令或在 TUI 选择「更新」触发；更新命令本身表达升级意图，无需二次确认。

官方安装脚本安装与直接解压的 Release 程序支持自更新，覆盖发布流程中的 Linux x64 / ARM64、macOS Intel / ARM64 和 Windows x64。源码安装仅提示按原安装方式升级，以保留本机构建的来源与用户修改。

更新目标为最新稳定版，仅在目标版本高于本机版本时替换；不提供预发布、指定版本或降级功能。

每次启动 TUI 后在后台检查一次，不阻塞启动与诊断，也不在同一运行期间定时检查。发现新版显示非阻塞提示，用户通过快捷键打开更新弹窗，以避免网络检查结果打断输入。

自更新以实际可执行文件所在的安装目录为目标，同时更新 `linklens` 和 `llens`，支持自定义安装目录，以避免两个独立程序出现版本不一致。

从 TUI 触发的更新成功后退出，提示用户自行重新启动；不自动启动新版 TUI。命令行更新完成后退出。

提供环境变量关闭 TUI 自动检查；显式执行更新命令仍检查并更新。关闭更新弹窗后，本次运行保留非阻塞提示，下次启动继续检查并提示，不持久化忽略版本或检查间隔。

自动检查失败时静默结束，不弹错误；显式执行更新命令时显示具体错误，并返回失败状态。检查失败与已经是最新版本必须区分。

从 TUI 选择更新后，下载与校验阶段留在界面中显示更新状态；失败后允许返回当前页面。两个新程序准备完成后才退出 TUI、恢复终端并执行程序替换，在普通终端输出安装结果。

实际安装目录缺少另一个命令时补齐，使成功更新后的主命令与短命令齐全且版本一致。

## 备选方案

- 仅提供命令或仅提供 TUI 入口：选择两个入口，使用户既可主动升级，也可在使用过程中发现新版。
- 发现新版直接下载并替换：选择用户主动触发，使升级时机由用户掌握。
- 源码构建也替换为官方二进制：选择保留安装来源边界，避免覆盖本地修改。
- 同时支持预发布、指定版本与降级：首版沿用稳定版升级路径，缩小版本选择与验证范围。
- 按 24 小时缓存检查结果或运行期间定时检查：选择每次启动检查，无跨启动检查间隔。
- 发现新版自动弹窗：选择非阻塞提示，保持页面输入与诊断操作连续。
- 只更新当前调用的命令：选择同时更新两个命令，避免主命令与短命令版本不同。
- 更新成功后自动启动新版 TUI：选择退出并由用户重新启动，使进程切换及页面状态重置可预期。
- 持久化设置开关或不提供检查开关：选择环境变量，支持离线及脚本环境，无需新增设置页面。
- 持久化忽略某个版本：选择每次启动继续提醒，无需保存跨运行的忽略记录。
- 自动检查失败时显示错误提示：选择静默失败，让手动更新承担错误反馈，避免网络不可用干扰诊断界面。
- 选择更新后立即退出 TUI：选择下载与校验完成后再退出，使下载失败仍可返回当前检测页面。
- 缺少另一个命令时拒绝更新：选择从同一 Release 补齐两个入口，保持安装结果一致。

## 后果与工程方案

两个入口需要共用更新逻辑，遵循 [双命令入口决策](0003-user-data-dir.md)；本记录不替代该决策，也不改变历史目录约定。

每次未关闭自动检查的 TUI 启动都会尝试请求版本信息。无需持久化检查时间与忽略版本，也不改变历史数据的持久化规则。

### 工程方案

- 官方 Release 构建内嵌来源标识、发布版本与构建目标，普通源码构建默认不具备该标识。标识用于区分分发来源，不作为签名认证。自更新目标沿用当前程序的构建目标，避免仅按运行机器架构选择错误附件。现有无自更新入口的版本须通过原安装方式升级一次。
- 采用 `LINKLENS_NO_UPDATE_CHECK=1` 关闭 TUI 自动检查。更新提示使用 `u` 打开弹窗，输入框优先消费字符；弹窗默认选中「稍后」，通过方向键或 Tab 选择，Enter 执行，Esc 仅关闭弹窗。首版采用键盘操作，不增加鼠标点击入口。
- 下载期间继续显示当前页面与更新状态，停止重复更新操作。取消或退出须停止下载、清理暂存文件，不执行替换；进入程序替换阶段后不接受取消。
- 复用官方 GitHub Release 与 `SHA256SUMS`，锁定检查所得的具体发布版本；校验归档后只接收该构建目标的两个程序，拒绝目录穿越与归档符号链接。首版沿用现有 HTTPS 与同源校验清单的信任边界，不新增独立签名协议。
- 版本检查总超时为 5 秒，下载与校验总超时为 180 秒，自动检查失败不循环重试。发现新版的提醒只反映版本可用，不保证安装目录可写；安装前核对目标目录、两个新程序及暂存条件，失败时保留原程序并报告原因，不自动提权。
- 解析当前程序的实际位置，更新该目录的两个命令；不修改其他 PATH 目录中的副本。遇到同目录兄弟命令的符号链接或不支持的目标文件类型时失败，不沿链接更新其他位置。缺少的普通命令从相同 Release 补齐。
- 同一安装目录仅允许一个显式更新流程；从用户触发后的身份核对、版本复核和下载开始，到暂存与最终替换结束连续持有目录锁，取消时释放。自动检查不持安装锁。锁内通过私有更新身份协议核对磁盘中现有两个命令的官方身份；若与当前进程的版本或目标不一致，则要求重启或按原安装方式修复，避免长时间运行的旧进程覆盖已被其他更新流程替换的程序。TUI 提示缓存不作为安装目标，用户选择更新后在锁内重新检查最新稳定版并锁定该发布。两个新程序均准备妥当后才替换，保留原文件备份与恢复记录；第二个程序替换失败时恢复第一个。若恢复也失败，报告实际文件状态并保留恢复材料；异常中断后的再次更新须先处理未完成的替换，不能把部分完成当作成功。恢复材料位于安装目录，属于更新流程，不写入历史数据目录。
- Windows 使用临时更新进程完成替换，原进程同步等待实际安装结果；运行中的旧程序重命名为备份，删除受占用影响时保留至后续清理。运行中程序可重命名的方案参考 [self-replace 官方实现](https://github.com/mitsuhiko/self-replace/blob/main/src/windows.rs)，原生安装验收见下方记录。选择同步等待是为了让命令返回实际失败状态；仅启动更新进程后退出无法满足结果反馈。安装成功仅指两个程序均已替换或补齐为目标版本，且更新进程已完成，不能在仅启动进程时报告成功。

完整规格、实施票据与验收证据记录在 [GitHub Issue #2](https://github.com/mel0nyrame/LinkLens/issues/2)。

### 验收边界

- 验证版本比较、相同版本、本机版本更高、非稳定发布与构建目标选择；区分已经最新和检查失败。
- 验证源码构建不覆盖本机程序，环境变量仅关闭自动检查，两个命令更新行为等价，自定义安装目录与缺少兄弟命令均按约定处理。
- 验证校验失败、附件缺失、目录不可写、归档越界、符号链接、第二个文件替换失败、恢复失败、并发更新与异常中断恢复。
- PTY 验证提示不打断输入、评分输入中的 `u`、弹窗 Esc 关闭、下载失败返回页面、下载取消与更新退出后的终端恢复。
- Rust 修改的测试、Clippy 和平台运行验收由推送后的 CI 执行，本地做静态检查；环境边界遵循 [验证环境决策](0005-validation-environment.md)。修改发布标识时由 CI 执行项目发布工具检查。
- 五个发布目标均需验证更新安装；Windows 必须验证运行中程序的替换、辅助进程交接与结果反馈。在目标平台验证前不声称该平台自更新已经可用。安装失败恢复承诺与普通成功路径分别验证。

可复现的终端验收入口见[任务导航](../agents/navigation.md)。macOS ARM64 / Intel 与 Linux musl ARM64 / x64 已运行核心、命令和临时目录安装测试；终端场景涵盖提示、输入、失败、取消、过期提示、已经最新与恢复。Linux x64 在仿真容器中运行。Windows x64 在 [Windows-2025 原生 CI](https://github.com/mel0nyrame/LinkLens/actions/runs/37044941819/job/110963983303) 中通过实际应用辅助进程替换运行中兄弟程序、锁交接、安装结果反馈、失败回滚及中断恢复测试；该结果不包含 Windows 终端的 PTY 交互验收。实际官方 Release 下载升级与用户安装目录未参与本地 fixture 验收；完整证据和待验收项由上述规格票保存。
