# 本地静态检查与 CI 运行验收

Status: implemented

## 问题

跨平台运行验收需要目标工具链、标准库、链接器和终端环境。为本地验收安装这些组件或下载容器镜像，会在开发机器的项目目录外产生持久文件与缓存，增加磁盘占用和维护成本。

## 决策

本地默认仅使用已有工具执行静态检查，包括文档链接、语法、格式与 diff。完成实现并通过本地检查后，在用户已授权的范围内推送任务分支，由 GitHub Actions runner 执行测试、Clippy、构建、安装与终端交互验收；交付时核对相应提交的 CI 结果。

该边界同时约束主代理和子代理。不得为验收在本机新增 Docker 镜像、Rust 工具链或目标标准库、SDK、全局依赖及仓库外编译缓存。所需平台环境在 CI runner 内准备；本地工具缺失时记录检查边界，不补装。已有验证产物的清理属于独立任务，不能据此删除其他任务或用户的环境。

## 备选方案

- 在开发机器安装跨平台标准库并使用 Docker 运行其他平台：可以在推送前得到运行证据，但项目外安装与持久缓存不符合开发环境约束。
- 仅做静态检查并直接交付：不会新增本机环境，但不足以验证双命令安装、跨进程事务和终端恢复；保留 CI 运行验收作为交付条件。

## 后果与风险

运行错误在推送后暴露，修复可能需要多轮 CI。静态检查通过不能代替运行验收；所需 CI 作业缺失时须先补齐入口，失败或未执行的检查如实报告。真实网络场景仍需按任务显式选择，不能用 fixture 结果推定真实服务可用。

本记录负责验证环境与执行位置，不改变 [自更新决策](0004-self-update.md) 的功能、安装恢复和平台覆盖要求。实际 CI 作业与终端脚本入口见 [发布维护](../../.github/RELEASING.md) 和 [任务导航](../agents/navigation.md)。
